# 引っ張って更新 + 更新検知バナー 設計

作成日: 2026-06-24

## 背景・課題

HIIT タイマーは GitHub Pages(`tatsuosakurai.github.io/hiit-timer/`)で配信し、
利用者はホーム画面に追加して standalone 表示で使う。Service Worker は無く、
ページ HTML のキャッシュ管理はブラウザ任せ。このため **新しいデプロイをしても
ホーム画面アプリが古い画面のまま反映されない**(再登録しないと更新されない)。

standalone 表示ではブラウザ標準の「引っ張って更新」も効かないため、手動の
リロード手段も無い。

## 目的

1. **引っ張って更新(pull-to-refresh)**: 画面を引っ張ってキャッシュを貫通した
   再読み込みを行い、最新版を取得できるようにする。
2. **更新検知バナー**: 新しいデプロイがあるとき、ユーザーに気づかせ、タップで
   更新できるようにする。

## アーキテクチャ上の前提

- **ソース**: `docs/HIITタイマー.dc.html`(DC フレームワーク。`<x-dc>` + `support.js`)
- **本番ビルド**: `index.html` = 固定ローダー(1〜296行、再生成で不変)+ 再生成
  されるデータ領域(`.dc` テンプレート + gzip 済み React モジュール + フォント)を
  埋め込んだ自己完結ファイル。
- 本機能は DC アプリのロジックと無関係な **素のブラウザ JS** として実装し、独立して
  動かす。

### 設置場所(再生成で消えない工夫)

- `index.html` の **固定ローダー領域の直後**(`</script>` と
  `<script type="__bundler/manifest">` の境目)に `<script>` を追記
  → いま本番で効く。データ再生成では書き換わらない領域。
- `docs/HIITタイマー.dc.html` の `<helmet>` にも同一の `<script>` を入れる
  → 将来 `.dc` から `index.html` を作り直しても拾われ、ソースと本番が乖離しない。
- 二重注入に備え `window.__hiitRefreshInit` で冪等ガードする。

## 機能仕様

### ① 引っ張って更新

- スクロール最上部から **下に ~90px 引いた**ときだけ発火。
  - `引っ張って更新 ↓` → しきい値超で `離して更新 ↑` に変化、指を離して実行。
- リロードは `?v=<timestamp>` を付与して **キャッシュ貫通**で再取得。
- **タイマー動作中は無効**: running 画面だけに存在する `svg[viewBox="0 0 320 320"]`
  (タイマーリング)を検知し、動作中はジェスチャを受け付けない → 誤爆ゼロ。

### ② 更新検知バナー

- `visibilitychange`(復帰)と初回起動で、自分自身に `HEAD` リクエスト
  (`cache: 'no-store'`)を投げ、`ETag`(無ければ `Last-Modified`)を取得。
- 起動時の値をベースラインとして保持し、復帰時の値と **異なれば**上部に
  「新しいバージョンがあります — タップで更新」バナーを表示。
- **自動リロードはしない**。タップ時のみ `?v=` 付きで更新 → タイマー中でも安全。
- 取得失敗時はバナーを出さない(引っ張って更新が手動フォールバックになる)。

## 誤爆・安全性

- 動作中(running)は引っ張り更新を完全に無効化。
- バナーは通知のみで自動リロードしない。
- いずれも明確なユーザー操作を起点とする。

## 検証

- 抽出した JS を `node --check` で構文確認。
- ローカルサーバで `index.html` を開き、スクリプトが読み込まれ初期化されること、
  設定画面での引っ張り表示・running 画面での無効化を確認。
